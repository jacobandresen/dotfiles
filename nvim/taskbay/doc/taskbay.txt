1. INTRODUCTION                                                 *taskbay-intro*

taskbay runs several coding agents side by side, each in a Git worktree, branch
and conversation of its own. Every agent is a pirate boat sailing out of the
taskbay; you are the fleet captain. You write the orders (a Markdown task),
review the plunder (the diff) and decide what goes into your branch.

Requirements: Neovim 0.12+, Git, snacks.nvim, and a coding agent (the default
driver runs pi; its extension needs npm once, see |:TaskbaySetup|). gh is
optional, for the GitHub integration.

==============================================================================
2. THE PIRATE CODE                                               *taskbay-code*

Every boat carries these articles in its orders (the prompt taskbay writes):

  1. Create and change files only inside your worktree.
  2. Implement only this task; follow the repository's instructions.
  3. Work through the "- [ ]" checklist and tick items off; for a local task
     that checklist is the only part of the task file a boat may touch.
  4. Run the relevant tests with a timeout and report actual results.
  5. Never commit, merge, push, close issues, install dependencies or remove
     worktrees without asking.

Committing, merging, deleting and publishing are the captain's actions, each
confirmed. The code lives in the prompt and worktrees are no sandbox: agents
run with your user's permissions.

==============================================================================
3. A VOYAGE                                                    *taskbay-voyage*

1. Space a n opens a blank task. Write "# Title", a blank line and the body,
   then |:write|. Tasks are plain files: .tasks/NNN-slug.md, with an optional
   .tasks/NNN.json for labels, assignees, milestone, state and relations.
2. Space a w opens the panel, the hub for everything. Enter starts a new task:
   taskbay creates <repo>-worktrees/task-N on branch task/N from HEAD and
   starts the agent in a tab of its own.
3. Rows show each agent's status (working, waiting, idle, no changes, ...) and
   checklist progress. d shows the diff, c sends an idle agent back to work,
   R restarts with the edited task in a new conversation (the worktree stays).
4. m stops the agent, commits the worktree and merges the branch into your
   checkout, after confirmation.

At most "max_agents" agents run at once; further tasks are prepared and wait.

==============================================================================
4. KEYS                                                          *taskbay-keys*

Global keys (see "keys" in |taskbay-options|; hints follow your mappings):

  Space a w       the task panel
  Space a n       write a new task
  Space a p, F6   start, show or hide the current tab's agent
  Space a v       the current task's text
  Space a s       send the file or selection to the agent (while one runs)
  Space a r       ask the agent for a read-only review of the task's changes
  Space a q       stop all agents and quit, after confirmation
  Space a G       turn the issue tracker integration on or off

In the panel (? shows the same list):

  Enter, 1-9      go to the task (a new one starts)
  p / x           start or resume the agent / stop it (work is kept)
  c               ask an idle agent to continue
  R               restart in a new conversation
  m               finish: commit, merge into your checkout, mark finished
  d / D           working diff / changes since the recorded base
  v / f           task text / fields
  X               delete the task, its worktree, branch and session
  n r [ ] q       new task / refresh / pages / close
  e / I           export as an issue / import issues (integration on)

In a task buffer: |:write| saves, Tab flips to its fields, Space a e asks the
task's agent to revise the text, Space a P publishes a tracker draft.

==============================================================================
5. COMMANDS                                                  *taskbay-commands*

:Taskbay                                                            *:Taskbay*
    Open the task panel.

:TaskbayNew [title]                                              *:TaskbayNew*
    Write a new task; with a title, create it at once.

:TaskbayImport [number]                                       *:TaskbayImport*
    Import an issue as a local task; without a number, pick one.

:TaskbayExport                                                *:TaskbayExport*
    Publish the current task as a new issue.

:TaskbayReload                                                *:TaskbayReload*
    Discard a tracker draft and fetch the issue again.

:TaskbayRemote                                                *:TaskbayRemote*
    Turn the issue tracker integration on or off.

:TaskbaySetup                                                  *:TaskbaySetup*
    One-time setup of the agent driver (for pi: npm ci of its extension).
    lazy.nvim runs the same through build.lua on install and update.

:TaskbayQuit                                                    *:TaskbayQuit*
    Stop all agents and quit, after confirmation.

==============================================================================
6. OPTIONS                                                    *taskbay-options*

>lua
  require("taskbay").setup({
    max_agents = 3,          -- live agents at once
    agent = "pi",            -- taskbay/agents/<agent>.lua
    remote = "github",       -- taskbay/remotes/<remote>.lua
    remote_enabled = false,  -- tracker integration off until enabled
    state_dir = vim.fn.stdpath("state") .. "/taskbay",
    keys = {},               -- any subset of: panel, new, agent, toggle, task,
                             -- send, review, quit, remote, revise, publish
    pi = { cmd = "pi", args = {}, provider = nil, model = nil },
  })
<
Options are stored in |g:taskbay|; later changes take effect at once, except
"keys", which setup() maps.

                                                                   *g:taskbay*
The current options table.

7. LUA API                                                        *taskbay-api*

require("taskbay").statusline()                         *taskbay.statusline()*
    The task tab's agent, task and status, for a statusline.

require("taskbay").review()                                 *taskbay.review()*
    The changed-files picker of the current task.

==============================================================================
8. DRIVERS                                                    *taskbay-drivers*

The agent and the issue tracker are driver modules: taskbay.agents.<name>
(pi ships) and taskbay.remotes.<name> (GitHub ships). Their interfaces, the
status file an agent reports through and the normalised issue shape are
described in the README.
